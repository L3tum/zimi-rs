# Themed Review Pipeline — 2026-08-21

Seven independent read-only reviews of `zimservice` (24 source files, ~8.5k LOC, 73 tests).
Each review ran in an isolated subagent with no visibility into the others' findings,
then was cross-referenced below. Corroboration counts (×N) indicate how many independent
reviews surfaced the same issue.

## Verdicts at a glance

| Theme | Verdict |
|---|---|
| Security | **BLOCK** |
| Architecture | ADEQUATE |
| Tests | ACCEPTABLE |
| Bugs | **BLOCK** |
| Performance | Needs work (6 HIGH) |
| Linting | MINOR-CLEANUP |
| Ponytail (over-engineering) | HAS-BLOAT |

**Overall: BLOCK as-is.** Not because of architecture or code quality — both are good —
but because of one critical security hole (the API's only credential is readable
anonymously) and two confirmed panics on ordinary non-ASCII content. Both classes are
small, well-localized fixes. Estimated path to shippable: ~1 day for P0, +1–2 days for P1.

## P0 — must fix before any non-local exposure (× = corroborating reviews)

### 1. `GET /settings` leaks every secret unauthenticated (SEC-CRITICAL, ARCH-HIGH) ×2
Auth middleware only gates mutating methods; `GET /settings` returns
`settings.all_grouped()` — the whole table in clear text, including
`access.admin_password` (the API's only credential), `torrent.password`,
`embedding.api_key`. The `PUT /settings` response re-leaks via echo, and
`SettingsCache::update` is an unvalidated, unwhitelisted write to any key
(`{"access":{"mode":"open"}}`, poisoned `embedding.endpoint` → content
exfiltration via the auto-embed loop, `search.max_limit` → i32 wrap in search).
**Fix:** redact secret keys from all responses; require token on `GET /settings`;
per-key whitelist + type validation on update; `access.*` immutable via API.

### 2. Byte-slice panics on non-ASCII (BUGS-HIGH, TESTS-HIGH, LINT) ×3
- `truncate_at_sentence` (zim/index.rs:424) — `text[..max_len]` in the rayon
  indexing loop; panics on essentially the first accented article → kills the whole
  index run / auto-index task, ZIM stuck at `indexing`.
- `chunk_text` (serve/handlers.rs:687) — `&text[start..hard_end]` byte math →
  panics `/chunks` + MCP `get_chunks`/`deep_search` on multi-byte content.
- `cmd_list truncate` (main.rs:300) — same class, LOW.
All 6 existing chunk tests are ASCII-only, so the suite is structurally blind.
**Fix:** char-boundary-safe slicing + non-ASCII regression tests (CJK, accents).

### 3. Single-file torrents can never install (BUGS-MEDIUM, core flow) ×1
`handle_complete` (poller.rs:352) always treats `content_path` as a directory;
for single-file torrents qB sets it to the *file*, `read_dir` fails →
`no .zim file found`. Breaks the core download→index pipeline for a common
Kiwix distribution form. **Fix:** if path `is_file()` and is a `.zim`, use it.

### 4. Auth fails open on empty password (SEC-HIGH, LINT) ×2
`mode=password` with empty `admin_password` (shipped default) → every request
passes with only a per-request `warn!`. **Fix:** hard startup error in
`build_state`; also seed `AUTH_PASSWORD` into `access.admin_password` (parsed at
config.rs:93, then never used) and make the compare constant-time.

## P1 — high, fix before real usage

### State machine / data integrity
5. **Concurrent indexing hazard** (BUGS, ARCH) ×2 — global `articles_staging`
   table TRUNCATEd per run, never cleared at start: two concurrent runs (poller
   auto-index + CLI `index --all` + resync) wipe each other's staged rows →
   silently missing articles; a crashed run leaves stale rows that re-index
   resurrects for changed files. `ZimManager.operation_lock` is declared
   "libzim is not thread-safe" and **never acquired** ×4 (ARCH, PERF, LINT, PONY).
   **Fix:** per-ZIM claim (UPDATE guard / advisory lock) + per-run staging.
6. **Direct-download lifecycle has no failure path** (BUGS, SEC, PONY) ×3 —
   network/stream/verify errors only get logged; row stuck `downloading`
   forever, consuming the `direct_active` budget; `.part` never cleaned;
   final unconditional `UPDATE status='complete'` **overwrites `cancelled`**
   (cancel is rolled back). Plus: `name` from `POST /downloads` is unvalidated →
   `../evil.zim` path traversal on the `.part`/rename; unbounded download size
   (disk fill) + SSRF (no host/scheme restrictions, error text readable via
   unauthenticated `GET /downloads`).
7. **`persist_to_db` discards `RETURNING id`** (BUGS) ×1 — ZIMs added at runtime
   keep `id: None`; collections CRUD rejects them until restart (`ZIM '<n>' not
   found`), listings silently drop them. **Fix:** write the id back into the cache.
8. **`?`-in-loop aborts**: `extract_qid` (index.rs:446 — one overflowing Q-number
   discards all earlier/later matches) and `index_zims` (index.rs:79 — one failing
   ZIM silently skips all remaining in `--all`; also the ZIM `Date` metadata is
   bound raw into a `DATE` column, so `"June 1, 2024"` kills the whole run;
   `index_status` is never set to `'error'`).
9. **CORS `Any` origin/method/header** (SEC-HIGH) — combined with the
   query-param token scheme, any malicious page can read token-gated responses
   from a logged-in admin's browser. **Fix:** explicit allowlist.

### Rate limiter (flagged by 5 of 7 reviews) ×5
10. `try_acquire` is check-then-`store` on two independent Relaxed atomics —
    concurrent requests over-admit (burst × parallelism); `capacity = burst *
    SCALE` is un-`checked_mul`'d on attacker-set values (wrap → 0 → 429-everything);
    `Retry-After` is emitted in **milliseconds** (RFC 9110: seconds or HTTP-date).
    **Fix:** CAS loop (or small mutex), checked math with a ceiling, seconds.

### Performance (PERF; several corroborated)
11. **`raw_content` copies the entire entry** before slicing Range
    (handlers.rs:577; 200MB video + `Range: 0-1023` = 200MB alloc+copy;
    N concurrent = N×200MB). The `zim` crate provides `Content::len()` /
    `Content::with(f)` for exactly this — copies only the requested slice.
12. **`open_zim` takes the global write lock + blocking `stat()` on every
    request** even on cache hit — all ZIM serving serialized behind one lock.
    **Fix:** read-lock fast path, TTL/watcher-driven invalidation.
13. **trgm `similarity > 0.1` cannot use the GIN index** (must equal
    `pg_trgm.similarity_threshold`, default 0.3) → seq scan + per-row trigram
    compute over 5M rows per search *and* per suggest. The
    `search.trgm_threshold` setting (default 0.3, exposed in the UI) is **dead**
    ×3 (PERF, LINT, PONY) — the honest fix is to wire the setting in.
14. **No vector index** — HNSW lines commented out in the migration; only built
    (plain `CREATE INDEX`, exclusive lock) at the end of a full per-ZIM embed
    pipeline. Every semantic search is a seq scan + full cosine.
15. **"Parallel" search engines are sequential**, and one pool connection is
    held through the embedding HTTP call (60s timeout) → hybrid search latency
    = sum, and pool exhaustion under concurrency.
16. **Indexing CPU waste**: full Readability pass per article (dwarfs
    strip_to_text) + `Regex::new` per entry (~5M compiles) + double UTF-8 decode
    in `extract_qid`. **Embed O(n²)**: `COUNT(*) ... embedding IS NULL` after
    every 100-row batch; `EXISTS` over 5M rows per ZIM every 60s (fix: partial
    index `WHERE embedding IS NULL`, drop the count, batch writes, allow 2–4
    concurrent chunks).
17. **`read_article` path**: full article `to_vec()` + CPU-bound deformat inside
    async workers, then truncated to 8000 chars (spawn_blocking / cap input).

### Config theater (ARCH-HIGH, SEC-MED, LINT, PONY) ×4
18. **8+ `Config` fields are parsed from env/TOML and never read**
    (`auth_password`, `search_workers`, `torrent_enabled`, `embedding_*`,
    `torrent_save_path/category`); README documents `AUTH_PASSWORD` as
    functional — it does nothing. Worse, an *active* lie: `EMBEDDING_ENDPOINT`
    etc. mark DB settings "locked by env" in the UI, but the env var has no
    runtime effect. **Fix:** collapse Config to the ~9 genuinely-used bootstrap
    fields; make `locked_env_settings` truthful; fix README. (config.rs 294→~150 LOC)
19. **500s leak raw Postgres error text** (constraint names, values) via
    `Error::Database` → `to_string()` in the catch-all (SEC-MED, LINT) ×2.
    **Fix:** fixed public message, full text to tracing.

## P2 — cleanup (grouped)

**Dead weight (all grep-verified, LINT + PONY) ×2–4:** `qid_cache` table + the
no-op `or_else(|| { let _ = (); None })` stub; `search_history` (written every
search, read nowhere; `zim_ids` never even written); `operation_lock`;
`cookies: reqwest::cookie::Jar` field; `Error::Search` (never constructed);
`find_zim`; `ZimMeta.uuid` (None at every source); `Checkpoint.started_at`;
`zims.embed_status/progress` columns; commented-out HNSW lines; `QbitClient`
`pause/resume/torrent_action/set_speed_limits` (~60 LOC, zero callers) + the
stale doc claiming a `qbittorrent_api` dependency that doesn't exist;
`RELEASE := 1` in Makefile; `axum` `multipart` feature (no multipart in src);
`_mtime` computed-and-dropped in `scan()`.

**Contracts & correctness nits:** OpenAPI `Download` docs say
`completed/failed` + `0–100` but code writes `complete/error` + `0–1` ×3;
`/health` hardcodes `"db_connected": true` (no DB ping) ×2;
`ORDER BY random() LIMIT 1` over 5M rows ×2; `put_settings` reports
`updated` including rejected keys; `update_collection` rename-conflict → 500
not 409; `(limit*2) as i32` wraps on poisoned `max_limit`; `LIKE` patterns
don't escape `%`/`_`; `COPY` hardcodes namespace `C` for 6.1+ UserContent
archives; `read_article_payload` truncates by chars but reports byte lengths;
`is_complete` treats `pausedDL` at ≥0.999 as complete; migrations are
`batch_execute`d without per-file transactions/checksums; `search_history`
insert is a fire-and-forget write on the hot path (delete with the table).

**Test gaps (TESTS):** settings cache has 0 tests; index.rs has 0 tests across
697 lines (escape_copy_text, extract_qid, checkpoint decision all untested);
rate limiter concurrency untested (would currently fail); poller state machines
untested (need mock-qB); OPDS entity-escaping + undated fallback untested;
`chunks_deterministic` is tautological; dead-pool URL trick copy-pasted 3×
(consolidate + timeout). Integration-test target list: the 10 targets from the
tests review (index E2E, checkpoint resume, re-index idempotency, hybrid search
vs real PG, auth matrix, rate-limit live-reload, direct-download lifecycle,
mock-qB full lifecycle, startup reconcile, settings semantics) are the right
scope for step 69.

**Refactors (architectural leverage, not urgency):**
- `mcp → serve::handlers` inverted dependency; QID/interlanguage SQL exists in
  3 shapes (ARCH, LINT, PONY) ×3 — extract a shared article/data layer;
- ToSql `&(dyn ToSql + Sync)` boilerplate in 4 shapes ×~44 sites — PONYTAIL's
  array-coercion trick (`let params: &[&(dyn ToSql+Sync)] = &[...]`) collapses
  the const-style shape; a helper for the builder shape is a wash (SKIP);
- two fingerprint-rebuild copies: ARCHITECTURE says unify, PONYTAIL says skip —
  **default: skip** (revisit at a 3rd copy), but the embed fingerprint is
  missing `embedding.batch_size` regardless — include the full effective config;
- `SettingsGet` trait: one implementor, never used as a bound → inherent methods.

**Big decision — OpenAPI (PONYTAIL vs recent work):** the utoipa layer is
~550 LOC + 19 response structs that are *never instantiated* (docs-only, and
already drifted — finding above). PONYTAIL recommends dropping the dep or
handwriting one static JSON; LINTING recommends fixing the docs. Options:
(a) keep utoipa + fix the two Download docs (status quo, accept the parallel
universe), (b) handwrite `openapi.json` (~150 LOC static, −1 dep, −~400 LOC
attributes/structs), (c) drop the spec. Decision needed — flag for the owner.

## Reviewer disagreements (surfaced deliberately)

1. **Fingerprint abstraction**: ARCHITECTURE (unify the two copies) vs PONYTAIL
   (skip; 2×25 lines is cheaper than the abstraction). → Adopt PONYTAIL (skip)
   but fix the missing `batch_size` in the embed fingerprint.
2. **OpenAPI**: PONYTAIL (drop/handwrite) vs LINTING (fix docs). → Owner decision.
3. **`direct_download` path**: PONYTAIL explicitly *keeps* it — it's the only
   download path in the default docker-compose (qB commented out). Agreed: keep,
   but fix P1#6.
4. **tests agent**: `REVIEW-PROJECT-TESTS` errored twice (transient infra);
   `REVIEW-TESTS` ran with identical full-codebase scope instead. No impact.

## What the reviews found clean (for the record)

SQL injection (all user input bound; COPY escaping covers `\ n r t`), XXE
(quick-xml default-features off), TLS (rustls, verification on, no OpenSSL),
path traversal in ZIM serve (exact-match names, opaque libzim keys), web UI
XSS (esc() everywhere), MCP (stdio-only, real pipe-based protocol test),
test determinism (0.02s, no sleeps/env mutation), per-request glue cost
(auth, rate limit, settings reads — all negligible), `zim::Zim` cross-thread
sharing (internally synchronized), the clippy/upgrade fallout
(rsplit/is_multiple_of/unescape changes verified behavior-preserving).
